# Slime

Slime 整体一共只有 3w 行代码，代码非常轻便，非常适合来学习 RL 框架。

入口位置在 `train.py` 和 `train_async.py`。

## 训练流程

1. 初始化：

   首先 `create_placement_groups` 函数来初始化 Ray 相关的资源。确保 GPU/CPU 资源可用。

   创建 Training model：`actor_model`、`critic_model`。

   创建 `RolloutManager`：支持 rollout 数据生成、SGLang 推理服务、placement group 绑定、offload 策略。

2. Training Loop：流程

   在异步训练的情况下，model 训练（`async_train`）和 rollout（`rollout_manager.generate.remote`）是解耦的。在 training loop 的流程上，训练过程中会用上一轮 rollout 生成的结果 train，同时下一轮的 rollout 也会 overlap 运行。

   在 `if (rollout_id + 1) % args.update_weights_interval == 0:` 的同步点更新 rollout 的权重。

   ```python
   for rollout_id in range(args.start_rollout_id, args.num_rollout):
       # Sync the last generation
       if rollout_data_next_future is not None:
           rollout_data_curr_ref = ray.get(rollout_data_next_future)

       # Start the next rollout early.
       if rollout_id + 1 < args.num_rollout:
           rollout_data_next_future = rollout_manager.generate.remote(rollout_id + 1)

       if args.use_critic:
           actor_trains_this_step = rollout_id >= args.num_critic_only_steps
           value_refs = critic_model.async_train(rollout_id, rollout_data_curr_ref)
           if actor_trains_this_step:
               ray.get(actor_model.async_train(rollout_id, rollout_data_curr_ref, external_data=value_refs))
           else:
               ray.get(value_refs)
       else:
           ray.get(actor_model.async_train(rollout_id, rollout_data_curr_ref))

       if should_run_periodic_action(rollout_id, args.save_interval, num_rollout_per_epoch, args.num_rollout):
           if (not args.use_critic) or rollout_id >= args.num_critic_only_steps:
               actor_model.save_model(
                   rollout_id,
                   force_sync=rollout_id == args.num_rollout - 1,
               )
           if args.use_critic:
               critic_model.save_model(
                   rollout_id,
                   force_sync=rollout_id == args.num_rollout - 1,
               )
           if args.rollout_global_dataset:
               ray.get(rollout_manager.save.remote(rollout_id))

       if (rollout_id + 1) % args.update_weights_interval == 0:
           # sync generate before update weights to prevent update weight in the middle of generation
           rollout_data_curr_ref = ray.get(x) if (x := rollout_data_next_future) is not None else None
           rollout_data_next_future = None
           actor_model.update_weights()

       if should_run_periodic_action(rollout_id, args.eval_interval, num_rollout_per_epoch):
           ray.get(rollout_manager.eval.remote(rollout_id))
   ```

3. **Rollout 模块**：Rollout 模块从 Buffer 取 prompt，用 SGLang 生成回答，并计算 reward，把结果写回 Buffer。
4. **Training 阶段**：Training 模块从 Buffer 取数据，用 Megatron 做前向/反向传播，更新模型权重。

支持**同步**和**异步**两种模式：

- **同步模式**：等 Rollout 生成完一批数据，Training 才开始训练。适合通用 RL。
- **异步模式**：Rollout 持续生成，Training 持续消费，两边互不等待。适合 Agentic RL（环境交互慢，不能让训练 GPU 空转）。

模型训练部分：`actor_model, critic_model = create_training_models(args, pgs, rollout_manager)`。

## Rollout

`rollout_manager.generate.remote(rollout_id + 1)`：Ray 在 `RolloutManager` 这个远程 actor 进程里执行 `generate(rollout_id + 1)`。

`_get_rollout_data` 执行 rollout 函数。

```python
data = call_rollout_fn(self.generate_rollout, self.args, rollout_id, self.data_source, evaluation=False)
```

这里的 `self.generate_rollout` 是启动时从 `args.rollout_function_path` 动态加载的函数，默认使用 SGLang 后端的话，会调用 `slime.rollout.sglang_rollout.generate_rollout` 来做 rollout。

从 data source 取 prompt/sample，调用 SGLang rollout engine 生成回答，并计算 reward，最后返回 `RolloutFnTrainOutput(samples=..., metrics=...)`。之后将返回的数据展平。`_compute_dynamic_global_batch_size`

`sglang_rollout.py` → `generate_rollout` → `run(generate_rollout_async(args, rollout_id, data_source.get_samples))`：

初始化 `GenerateState`。

把每个 group 提交成异步任务 `generate_and_rm_group(...)`。这里的单个 group 指的是 GRPO 的同一个训练样本/prompt 对应的多条 rollout。

`sglang_rollout.generate` 会先做 tokenizer（为了和训练侧的 tokenizer 对齐），之后调用 SGLang 的 generator 接口完成推理，拿到 sample 的结果。

`async_rm` 完成 reward model 的计算。`rm_type` 有：

- deepscaler：DeepScaler 数学类规则 reward
- dapo：DAPO 数学类规则 reward
- math：用 `grade_answer_verl(response, label)` 判断答案是否正确，对是 1，错是 0
- f1：算 response 和 label 的 F1
- gpqa：GPQA 选择题/问答 reward
- ifbench：IFBench instruction following reward
- remote_rm：支持配置远程的 reward HTTP 服务

`_log_rollout_data`：打日志和 metrics。

`_convert_samples_to_train_data`：做格式转换，转换成训练所需要的格式。

`_split_train_data_by_dp`：rollout train data 按训练侧 DP 切成 `dp_size` 份，然后放进 Ray object store，供每个 DP rank 取自己的那份。

默认的例子里面的 rollout 函数是单轮的，可以通过函数定制化修改 rollout 的函数来实现 Agentic RL。代码里面也有对应的例子。

1. `examples/search-r1/generate_with_search.py`：搜索增强 rollout，自定义生成逻辑。
2. `examples/tau-bench/generate_with_tau.py`：tau-bench 工具/环境类 rollout。
3. `examples/strands_sglang/generate_with_strands.py`：strands agent 风格的 SGLang 自定义 rollout。
