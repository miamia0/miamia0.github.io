# Megatron

## FSDP

代码目录：megatron/core/distributed/fsdp 

DDP

每块GPU都拷贝一份参数，数据并行按照 batch 维度拆分成micro-batch，一块GPU 做 参数的reduce。

forward： 和单个GPU 是一样的。

backword 阶段：和单GPU 也是一样的，单卡独立计算精度。之后所有的GPU push 梯度到梯度收集的GPU，聚合完成后（平均值后），再pull回来。

fsdp 是 zero3的实现。在megatron里，如果 args 配置了使用use_megatron_fsdp，那会走到 fsdp里。默认走 DDP

```cpp
 if wrap_with_ddp:
        if args.use_torch_fsdp2:
            assert HAVE_FSDP2, "Torch FSDP2 requires torch>=2.4.0"
            DP = torch_FSDP
        elif args.use_megatron_fsdp:
            DP = megatron_FSDP
        else:
            DP = DDP
```

之后给每一个model 包一层 pp，至于为什么是多个model，在设置virtual_pipeline_model_parallel_size 非空的情况下，会有多个model。其他情况下都只有一个model。

```cpp
            if args.use_megatron_fsdp:
                dp_init_kwargs["pg_collection"] = pg_collection
            model = [
                DP(
                    config=config,
                    ddp_config=ddp_config,
                    module=model_chunk,
                    # Turn off bucketing for model_chunk 2 onwards, since communication

                    **dp_init_kwargs,
                )
                for (model_chunk_idx, model_chunk) in enumerate(model)
            ]
```

megatron 的 fsdp 支持 四种模式：

no_shard，optim，optim_grads，optim_grads_params

no_shard：类似于 DDP

- 每个 data parallel rank 都持有一整份模型参数
- 梯度同步走常规 DP 语义，在 backward 后做聚合
- 不做 ZeRO/FSDP 那种参数，梯度，优化器状态的切分
- 所以它通常通信更简单，但显存占用更高

optim：ZeRO-DP 分割优化器的状态，将 optimizer 的状态拆分到不通的GPU上。

optim_grads:ZeRO-2。分割梯度状态。将梯度分割到不同的GPU上，每次反向传播都需要做一次 reduce-scatter。优化器计算完更新量之后，再做一次 all-gather。

optim_grads_params:ZeRO-3。将参数拆分到不同的GPU上，每次forward进行一次ALL-gather：为什么这里做了模型参数的拆分，但是实际上并不是 TP 呢？因为这里实际上只是为了省显存，本质上还是为了做数据并行。

看起来像是 编译器优化级别：)

另外 Megatron 的FSDP 实现也支持了 CP 和 EP，之后会专门出一个文章讲讲 CP 和 EP。

支持了混合精度训练。

### __init__ 阶段

**_init_fsdp_param_and_grad_buffer**

创建了 ParamAndGradBuffer，用于对参数和梯度做通信管理。

ParamAndGradBuffer 会被用来创建两条通信流水线：GradReducePipeline & AllGatherPipeline

GradReducePipeline 负责把梯度按照 bucket 异步做 reduce。梯度怎么尽早 reduce / reduce-scatter

AllGatherPipeline 负责参数什么时候被 all-gather 回来给 forward/backward 用

**_register_fsdp_hooks**

因为 Megatron的 FSDP 实际上是以独立插件的形式实现的，与model实现解耦。所以实际上参数分片等逻辑都是在 hooks 内部实现的。

1. 给每个模块挂上 _training_state: IDLE, FORWARD, PRE_BACKWARD,POST_BACKWARD
2. forward _register_pre_forward_param_unshard_hook
    1. 做参数的 _pre_forward_param_unshard：all_gather_and_wait_parameters_ready：
        
        基于 AllGatherPipeline 实现参数 gather
        
3.  backward 前 backword _pre_backward_param_unshard 
    1. 类似于 _pre_forward_param_unshard，做参数的gather
4. backword 后：
- 把 param.grad 累积到 main_grad
- 触发 GradReducePipeline.reduce_gradients(...)
- backward 完后释放这个模块参数对应的 bucket
1. _release_module_fp8_transpose_cache
    - 把当前模块浅层参数里的 FP8 transpose cache 丢掉/标记失效
    - 目的是回收这部分额外显存，避免 forward 后继续保留
    - 在all_gather_and_wait_parameters_ready 阶段会做fp8 的transpose_cache
    
    ```cpp
         if wait_bucket_ready:
                for param in params:
                    bucket_id = self.param_and_grad_buffer.param_to_param_group[param]
                    ag_pipeline.wait_bucket_ready(bucket_id, bwd)
                    if bwd and is_float8tensor(param):
                        fp8_create_transpose_cache(param)
    
    ```
    
2. _root_pre_backward 
3.  _root_post_backward
    1. 最后做一次 reduce_gradients，避免梯度漏同步

### GradReducePipeline：

  负责 backward 后的梯度同步：

- 先把参数添加到 self.bucket_grad_ready_params[bucket_id] 集合中。
- 当一个 Bucket 里面中的所有参数的梯度都计算完成后（get_ready_bucket_group_for_reduction），就可以开始通信操作。
- wait_for_previous_grad_reduce
    - 检查当前的通信量是否超过了通信队列容量，等待直到有通信quota
- _bucket_group_gradient_reduce
    - 在  # DP-Shard Gradient Reduction 阶段，会做 DP 组内的通信。
        - 在no shard 的时候
        - 非 no shard reduce_scatter_tensor

用 main_grad 相关 buffer，做 reduce-scatter/all-reduce，处理梯度从“完整/局部”到“reduced shard”。

### AllGatherPipeline：

用 model_weight 相关 buffer，做 all-gather，处理参数从“shard”到“可计算的完整 bucket”。

## SP & CP

序列并行：

Megatorn SP

随着上大模型下文长度越来越长，部分sequence 的激活值在训练时占用的显存会变大。 SP 按照序列做切分，不同部分按照 TP 组分到不同的 GPU 上。

![image.png](attachment:e4ab132c-434c-4c97-b07f-8445d90b29a5:image.png)

![image.png](attachment:cd18defe-4bae-4f67-a9e2-65b26c99b70e:image.png)

在进入Tensor Parallel区域之前，进行All-gather，收集全量的数据，TP 结束后，通过scatter，按照sequence再次切分。

Megatron 支持 CP 用于解决SP 没解决的 attention 计算的序列并行的问题。

cp 支持 p2p，all_gather, a2a, a2a+p2p 的 cp_comm_type 配置。p2p 是 ring attention模式，a2a 是 ulysses 的模式。a2a+p2p 是混合两种cp的方案：在单节点组内做ulysses，多节点之间做p2p。默认走p2p。

因为megatron 现在代码的cp实现直接用的是 transfomer-engine ，要看具体的实现需要到transformer-engine 仓库里面来看。相关实现在 TransformerEngine/transformer_engine/pytorch/attention/dot_product_attention/context_parallel.py 。a2a实现在 flash_attn_a2a_communicate，p2p实现在 flash_attn_p2p_communicate。

ulysses attention 的实现是将从按序列切分 到 按 head 切分，需要做一次a2a的通信。

```cpp
def reorder_seq_chunks_for_a2a_before_attn(x, chunk_ids_for_a2a, seq_dim, cp_size):
    """Reorder sequence chunk for A2A communication before attention compute."""
    # [cp, b, s, h//cp, d] -> [b, cp, s, h//cp, d]
    # [cp, s, b, h//cp, d] -> [cp, s, b, h//cp, d]
    x = x.movedim(0, seq_dim).contiguous()
    # [b, cp, s, h//cp, d] -> [b, cp*2, s//2, h//cp, d]
    # [cp, s, b, h//cp, d] -> [cp*2, s//2, b, h//cp, d]
    x = x.view(*x.shape[:seq_dim], cp_size * 2, -1, *x.shape[(seq_dim + 2) :])
    # reorder the sequence chunks
    x = torch.index_select(x, dim=seq_dim, index=chunk_ids_for_a2a)
    return x
    
 x = reorder_seq_chunks_for_a2a_before_attn(
      x, chunk_ids_for_a2a, seq_dim, cp_size
 )
 # [b, cp*2, s//2, h//cp, d] -> [b, cp*s, h//cp, d]
 # [cp*2, s//2, b, h//cp, d] -> [cp*s, b, h//cp, d]
 # [b, h//cp, cp*2, s//2, d] -> [b, h//cp, cp*s, d]
 a2a_outputs[i - 2] = x.view(
     *x.shape[:seq_dim], -1, *x.shape[(seq_dim + 2) :]
```
